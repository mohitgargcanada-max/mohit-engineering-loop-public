# MEL-007 - Plan author, not coordinator, decides who may approve a plan

Branch: claude/mel-007-plan-author, cut from main 2a3ea7f.
Builder: Claude (claude-sonnet-5-5). Plan review and final inspection: Codex.

Origin: MEL-006 task state. `approve_plan` refuses a reviewer equal to `state['coordinator']`, which `init` sets from the
owner and `revise-plan` from the actor; `acknowledge` and `takeover` never change it. A plan written by the other provider
(adopted at init) or an ownership move leaves the wrong provider refused and the plan's own author eligible. MEL-006 needed a
no-op `revise-plan` by the new owner to pass the gate.

## Accepted scope

- H1: State stores `plan_author` (native provider) at `init` and `revise-plan`; new `--plan-author claude|codex` flag on both, default provider(owner) at init and provider(actor) at revise-plan.
- H2: `init` with `--adopt` raises StateError when the adopted files include the plan file and no adopted builder equals `plan_author`; if the plan is not among adopted files the check is skipped and documented.
- H3: `approve_plan` requires a native reviewer different from `plan_author`; legacy state without `plan_author` falls back to `coordinator`.
- H4: `acknowledge` and `takeover` leave `plan_author` unchanged.
- H5: Regression test: adopted codex plan with claude owner accepts claude approval and refuses codex; both fail on current code.
- H6: Regression test: the H5 result is unchanged after a handoff acknowledged by the other provider and after a takeover.
- H7: Regression test: legacy state without `plan_author` keeps the coordinator rule; `--plan-author` on revise-plan replaces the author.
- H8: One line each in `references/delivery.md` (plan review) and `references/handoffs.md`; README task index and status line mention MEL-007.
- H9: Full `python -B -m unittest discover -s tests -v` and `python -B scripts/validate.py` pass; no other behavior change.
