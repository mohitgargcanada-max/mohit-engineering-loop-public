# MEL-009 - Single-provider mode, plan-quality gates, router backends, project fit

Branch: claude/mel-009-single-provider, cut from main eb45602.
Builder: Claude (claude-sonnet-5-5). Plan review and final inspection: Codex when available, else under the single-provider rule below.

Origin: owner, 2026-11-01: "there could be a scenario where codex might not be available at all; claude should be able to do all
its work using the proper engineering principles laid out in the skill ... the skill should work and adapt when either claude or
codex is unavailable." Today `independent()` demands the other native provider to inspect, `approve_plan` refuses a same-provider
reviewer, and `inspect` refuses when every builder equals the reviewer; only the plan has a waiver. One provider out means a
hard stall. A Fable review of the skill against a private project (2026-11-01) and OmniRoute's removal from the owner's machine add K5-K6.

## Accepted scope

- K1: Single-provider mode. State field `single_provider` = {available: claude|codex, reason, approved_by, entered_revision, date}, set with `--single-provider claude|codex --reason TEXT --approved-by TEXT --plan-model MODEL` on `init` or the gated `single-provider enter` command; left with `single-provider leave` (entering keeps reviews, leaving voids them; the unavailable provider's actions are refused while on) (recorded in `single_provider_history`). While active, `approve-plan` and `inspect` accept the available provider as reviewer even when it built or planned, only if: (a) the report states `fresh_session: true` and `built_nothing: true`; (b) `--model` is given and differs from every builder model in the ledger (and from the recorded plan model); or, when the builder is already the strongest available model, `--same-model REASON` plus `--user-approval TEXT` allows a fresh same-model session, recorded as such; (c) the report has a non-empty `adversarial` list (what could be wrong, a control that could fail). Backend reviewers stay refused; a builder labelled `harness@backend` gets no relaxation (the model rule applies to it too), so a native build cannot be relabelled to pass. Applies symmetrically (codex-only when claude is out). Legacy builders with no ledger model are refused in the mode (fail closed). The high-risk `eval` judge follows the same rule. `ready`, `merged` and `show --brief` print `SINGLE-PROVIDER REVIEW (<reason>)` (stderr for ready/merged so the JSON stays parseable, plus a state field); leaving the mode never retroactively upgrades those reviews.
- K2: SKILL.md (one short paragraph), `delivery.md`, `standards.md` (reviewer table rows), `handoffs.md` and `capacity.md` (capacity `unknown`/`exhausted` leads to entering the mode) describe the mode exactly as the helper enforces it.
- K3: Tests (stdlib unittest): a claude-only task reaches ready and merged with a different-model fresh reviewer; refused without the mode; refused when reviewer model equals builder model unless `--same-model`; refused for backend reviewers; label shown by `show --brief`, `ready` and `merged`; codex-only symmetry; legacy state unaffected. Each fails on the current helper.
- K4: Plan quality (ideas only, from github/spec-kit): (a) `approve-plan` refuses while the plan file contains `[NEEDS CLARIFICATION: ...]`; (b) approve-plan lists criterion ids absent from the plan or lacking a `proof` line (warn, recorded; see plan note on why not refuse); (c) a plan template with lean gates (smallest change, reuse before add, no speculative infrastructure) answered yes/no, each "no" needing a one-line reason, in `delivery.md`, with `discipline.md` pointer. Tests for (a) and (b).
- K5: `backends.md` and `unattended.md`: replace OmniRoute as the configured router (removed from the owner's machine 2026-11-01) with OpenRouter direct (paid key; private work only where provider terms allow) and freellmapi (local router at 127.0.0.1:3001, free tiers, public or non-sensitive work only, pin exact model ids, never `auto` where reproducibility matters). Backend rules unchanged (no plan approval, no inspection). Labels `harness@backend` stay (`claude@openrouter`, `claude@freellmapi`). Historical OmniRoute notes shortened and dated; references in `standards.md`, `context.md`, `ATTRIBUTION.md`, SKILL.md updated to match.
- K6: Project fit: (a) `snapshot()` counts every untracked non-ignored file as dirty; document that tasks run from a fresh worktree (the smaller safe option; an ignore option would weaken the clean-tree proof); (b) `delivery.md`: a project may name its own merge script and proof runner (for example `integrate_into_master.py`, serial pytest runner) and local delivery uses them; (c) `delivery.md`: each task maps to the project's tracker id and the project's definition of done (journal, tracker, spec) is a `ready` criterion when the project has one.
- K7: `scripts/validate.py` and `python -B -m unittest discover -s tests -v` pass; README task index and status line and `docs/VALIDATION.md` carry MEL-009; SKILL.md version 0.5.0; no other behavior change.
